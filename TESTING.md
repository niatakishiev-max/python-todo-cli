# Тестирование ToDo CLI

## Цель тестов

Автотесты проверяют базовую бизнес-логику ToDo-приложения и работу с JSON-хранилищем.

Проект постепенно разделяет:

- бизнес-логику, которую можно тестировать напрямую;
- консольный интерфейс, который отвечает за `input()` и `print()`;
- работу с файлом данных, которую можно проверять через временные файлы.

## Как запустить тесты

Установить зависимости:

```bash
python -m pip install -r requirements.txt
```

Запустить тесты:

```bash
python -m pytest
```

## Что покрыто тестами

### Нормализация задач

Проверяется функция `normalize_task()`.

Сценарии:

- задача в старом формате строки превращается в словарь;
- задача в формате словаря сохраняет нужные поля;
- задача с недостающими полями получает значения по умолчанию.

### Сохранение и загрузка JSON

Проверяются функции `save_data()` и `load_data()`.

Сценарии:

- загрузка отсутствующего файла возвращает пустые списки;
- активные и выполненные задачи сохраняются во временный JSON-файл;
- сохранённые данные корректно загружаются обратно.

Для этих проверок используется fixture `tmp_path`, чтобы тесты не трогали настоящий файл `tasks.json`.

### Перенос задачи в выполненные

Проверяется функция `move_task_to_completed()`.

Сценарии:

- задача удаляется из активного списка;
- задача добавляется в список выполненных;
- поле `done` меняется на `True`.

### Возврат выполненной задачи

Проверяется функция `restore_completed_task()`.

Сценарии:

- задача удаляется из списка выполненных;
- задача возвращается в активный список;
- поле `done` меняется на `False`.

## Используемые возможности pytest

- `assert` для проверки результата;
- `tmp_path` для создания временных JSON-файлов во время теста.

## Что можно добавить дальше

- тесты для проверки напоминаний;
